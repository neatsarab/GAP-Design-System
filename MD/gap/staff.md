# ระบบรับรองมาตรฐาน GAP (ฝั่งเจ้าหน้าที่)

หน้าจอนี้เป็น **ระบบสำหรับเจ้าหน้าที่กรมวิชาการเกษตร** ใช้ในการจัดการคำขอรับรองมาตรฐาน GAP ตั้งแต่การรับคำขอ ตรวจประเมินแปลง ไปจนถึงการอนุมัติใบรับรอง

---

# 1. โครงสร้างหน้าจอหลัก

หน้าจอประกอบด้วย 3 ส่วนหลัก
GAP staff System
│
├─ Sidebar Navigation
├─ Request List / Search
└─ Workflow Processing

---

# 2. Sidebar Menu (เมนูด้านซ้าย)

เมนูใช้สำหรับเข้าถึงโมดูลต่าง ๆ ของระบบ

## ข้อมูลภาพรวม
- Dashboard แสดงสถิติคำขอ
- จำนวนคำขอ
- สถานะการดำเนินงาน

---

## ยื่นขอใบรับรองแบบเดี่ยว

เมนูสำหรับจัดการคำขอของ **เกษตรกรรายเดี่ยว**

### เมนูย่อย

- **ยื่นขอใบรับรอง**  
  สำหรับบันทึกคำขอใหม่

- **รายการคำขอ**  
  แสดงรายการคำขอทั้งหมดในระบบ

- **นัดตรวจแปลง**  
  กำหนดวันตรวจประเมินพื้นที่

- **ผลการตรวจแปลง**  
  บันทึกผลการตรวจประเมิน

- **เสนอแปลงต่อ CC**  
  เสนอผลการตรวจต่อคณะกรรมการ

- **บันทึกครั้งที่เสนอ CC**  
  บันทึกข้อมูลการเสนอพิจารณา

- **บันทึกผลจาก CC**  
  บันทึกผลการพิจารณาจากคณะกรรมการ

---

## ยื่นขอใบรับรองแบบกลุ่ม
ใช้จัดการคำขอ **การรับรองแบบกลุ่มเกษตรกร**

---

## ข้อมูลใบรับรอง
จัดการข้อมูลใบรับรองที่ออกแล้ว

---

## ติดตาม-แจ้งเตือน
ระบบแจ้งเตือนสถานะคำขอ

---

## รายงาน
สร้างรายงาน เช่น

- รายงานคำขอ
- รายงานการตรวจประเมิน
- รายงานการรับรอง

---

# 3. หน้ารายการคำขอ (Request List)

หน้าจอนี้ใช้สำหรับค้นหาและจัดการคำขอรับรอง

## ตัวกรองข้อมูล

เจ้าหน้าที่สามารถค้นหาคำขอโดย

- วันที่ยื่นคำขอ
- ประเภทคำขอ
- ประเภทใบรับรอง
- สถานะใบรับรอง

ปุ่มการทำงาน

- **ค้นหา**
- **ล้างตัวกรอง**

---

## ตารางรายการคำขอ

| Field | รายละเอียด |
|------|-------------|
| หมายเลขคำขอ | เลขอ้างอิงคำขอ |
| Column | ข้อมูลคำขอ |
| วันที่ยื่นคำขอ | วันที่ยื่นคำขอ |
| สถานะคำขอ | สถานะกระบวนการ |
| Action | ปุ่มจัดการคำขอ |

ตัวอย่างสถานะ

- รอตรวจคำขอ
- รอนัดตรวจแปลง
- อยู่ระหว่างพิจารณา
- อนุมัติแล้ว
- ไม่ผ่าน

---

# 4. Workflow การดำเนินการรับรอง GAP

ระบบมี **Workflow การดำเนินงาน 6 ขั้นตอน**
1 ข้อมูลคำขอ
2 นัดตรวจแปลง
3 ผลตรวจแปลง
4 เสนอแปลงต่อ CC
5 บันทึกครั้งที่/ผล CC
6 ลงนาม


---

# 5. ขั้นตอนที่ 2 : นัดตรวจแปลง

เจ้าหน้าที่กำหนดช่วงเวลาการตรวจประเมินพื้นที่

## ข้อมูลที่ต้องกรอก

| Field | รายละเอียด |
|------|-------------|
| จากวันที่ | วันที่เริ่มตรวจ |
| ถึงวันที่ | วันที่สิ้นสุด |

ปุ่มการทำงาน

- **ย้อนกลับ**
- **นัดตรวจแปลง**

เมื่อบันทึกแล้ว ระบบจะ

- อัปเดตสถานะคำขอ
- แจ้งเตือนผู้เกี่ยวข้อง

---

# 6. สถานะการทำงานของคำขอ

ตัวอย่างสถานะที่ระบบรองรับ

| สถานะ | ความหมาย |
|------|-----------|
| รอตรวจคำขอ | เจ้าหน้าที่กำลังตรวจเอกสาร |
| รอนัดตรวจแปลง | เตรียมกำหนดวันตรวจ |
| ตรวจแปลงแล้ว | อยู่ระหว่างบันทึกผล |
| เสนอ CC | ส่งเข้าคณะกรรมการ |
| อนุมัติ | ได้รับการรับรอง |
| ไม่อนุมัติ | ไม่ผ่านการรับรอง |

---

# 7. Action ที่เจ้าหน้าที่สามารถทำได้

เจ้าหน้าที่สามารถ

- เปิดดูคำขอ
- แก้ไขข้อมูล
- นัดตรวจแปลง
- บันทึกผลการตรวจ
- ส่งเรื่องเข้าคณะกรรมการ
- บันทึกผลการพิจารณา
- ออกใบรับรอง

# 9. Information Architecture (IA) – ระบบเจ้าหน้าที่ GAP

Information Architecture นี้อธิบาย **โครงสร้างโมดูลของระบบฝั่งเจ้าหน้าที่** เพื่อให้เห็นภาพการจัดกลุ่มฟีเจอร์และหน้าจอในระบบ

# 9.2 Information Architecture ตาม Workflow

โครงสร้างหน้าจอที่สัมพันธ์กับ **ขั้นตอนการทำงานของเจ้าหน้าที่**
Application Processing
│
├─ Step 1 : ข้อมูลคำขอ
│ ├─ ข้อมูลผู้ยื่นคำขอ
│ ├─ ข้อมูลแปลง
│ ├─ ข้อมูลพืช
│ └─ เอกสารแนบ
│
├─ Step 2 : นัดตรวจแปลง
│ ├─ กำหนดช่วงวันตรวจ
│ └─ แจ้งเตือนเกษตรกร
│
├─ Step 3 : ผลตรวจแปลง
│ ├─ ผลการตรวจพื้นที่
│ ├─ ข้อบกพร่อง
│ └─ ผลวิเคราะห์ตัวอย่าง
│
├─ Step 4 : เสนอแปลงต่อ CC
│ ├─ สรุปรายงาน
│ └─ ส่งเข้าพิจารณา
│
├─ Step 5 : บันทึกผล CC
│ ├─ บันทึกผลประชุม
│ └─ ผลการพิจารณา
│
└─ Step 6 : ลงนาม
├─ ออกใบรับรอง
└─ Generate Certificate

# 9.4 สิทธิ์ผู้ใช้งานในระบบ

ระบบเจ้าหน้าที่อาจแบ่ง Role เช่น

| Role | สิทธิ์ |
|-----|------|
| เจ้าหน้าที่ตรวจคำขอ | ตรวจสอบเอกสาร |
| เจ้าหน้าที่ตรวจแปลง | บันทึกผลตรวจ |
| เจ้าหน้าที่ประสานงาน | นัดตรวจแปลง |
| คณะกรรมการ (CC) | พิจารณาอนุมัติ |
| ผู้มีอำนาจลงนาม | ลงนามใบรับรอง |
| Admin | จัดการระบบ |
